# RKGB (Research Knowledge Graph Builder)

# AI Engineering Implementation Prompt

## Step A2 — Configuration System

You are continuing the implementation of the Research Knowledge Graph Builder (RKGB).

The repository has already been bootstrapped during Step A1.

Do **NOT** redesign the architecture.

Implement only the Configuration System.

The goal is to create a production-grade configuration framework that supports every current and future component of RKGB.

The implementation must be modular, strongly typed, extensible, environment-aware, and dependency-injection friendly.

---

# Architectural Context

RKGB follows the following architecture:

```text
Presentation Layer
(API, CLI, Pipelines, Agents, Kafka)

            │
            ▼

     Processing Engine

            │
            ▼

     Application Layer

            │
   ┌────────┴────────┐
   ▼                 ▼
Command Bus      Query Bus

   │                 │
   ▼                 ▼
Handlers        Query Handlers

            │
            ▼

       Domain Layer

            │
            ▼

    Repository Layer

            │
            ▼

 Infrastructure Layer
```

The Configuration System belongs to the Infrastructure Layer.

Every layer depends on configuration.

No component should read environment variables directly.

# Design Principles

The Configuration Framework must follow:

* SOLID
* Clean Architecture
* Dependency Injection
* Strong typing
* Immutable configuration objects
* Single source of truth
* Separation of concerns
* Twelve-Factor App principles

Configuration consumers must never access `.env` files directly.
